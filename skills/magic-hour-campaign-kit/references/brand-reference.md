# Reuse the approved brand reference

Read the project's existing brand guidance first. Update that source when authorized; do not create a second conflicting registry. If none exists and this is repeat work, keep one short Markdown brief alongside the user's creative files. Never store API keys or signed upload/download URLs as durable brand assets.

Use this minimum structure, omitting unknown or irrelevant fields:

```markdown
# Campaign reference

Approved source: local durable image path and original Magic Hour project ID, if any
Identity to preserve: exact label, shape, cap, material, color, logo
Brand assets: original logo path; palette; licensed font name/path
Exact copy: headline; CTA; supplied destination URL, if requested
Placements: canvas, media panel/crop, copy regions, platform overlays
Motion/audio: requested movement, duration, allowed holds/loops, audio treatment
Accepted outputs: local paths, project IDs, what was visually checked
Known limitations: failed criteria, watermarks, source detail, untested uses
```

Treat each new brief as a change against this reference. Copy changes require composition, not new media. A changed product source invalidates identity approval for derived stills and videos. A new aspect ratio requires a new layout check, not automatic regeneration. A changed motion request requires a video check even if the still is unchanged. Preserve accepted assets and repair only what the change affects.

Do not infer that an asset is approved because its file exists. Record who approved it or that the agent accepted it under delegated creative authority. If source color is uncertain under dramatic lighting, retain that uncertainty rather than calling it a verified brand-color match.
